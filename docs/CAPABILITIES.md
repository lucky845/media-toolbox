# 能力矩阵（Phase 0 交付物 3/8）

> 这是**唯一的一份**能力真相。站内「能力与限制」页、README、UI 上的 `CapabilityBadge` 都从这里派生；不允许各写一份。
> 图例：✅ 完整支持　⚠️ 有限支持（附原因）　❌ 不支持（附替代路径）　— 不适用

## 1. 图片

| 功能 | Web（在线版） | 桌面版 | Web 侧的原因 / 限制原文 |
|---|---|---|---|
| JPEG / PNG / WebP / GIF / BMP / TIFF 解码 | ✅ | ✅ | — |
| AVIF 解码（浏览器原生） | ✅（Chrome 85+/FF 93+/Safari 16.4+） | ✅ | canvas/img 解码走浏览器；不解码时明确报 `UNSUPPORTED_FORMAT` |
| AVIF 编码 | ⚠️ 默认关闭 | ✅ | ravif 约 +1.5–2 MB br；`capabilities().image.avif=false` 时按钮不显示，不做「点了才失败」 |
| 压缩（有损 JPEG/WebP） | ✅ ≤20 MP | ✅ 无上限（流式） | 单线程 wasm + Worker；`cancel.hard=false`，取消是终止 worker |
| 压缩（无损 PNG/WebP） | ✅ | ✅ | PNG 无损优化 oxipng 在 Web 端按体积预算决定是否开启 |
| 裁剪 | ✅ | ✅ | — |
| 旋转 / 翻转 | ✅ | ✅ | — |
| 亮度 / 对比度 / 饱和度 | ✅ | ✅ | — |
| 缩放（保持宽高比，Lanczos3 等 5 种滤波） | ✅ | ✅ | 同一份 Rust 核，改一处两端生效（Phase 1 验收项） |
| 保持宽高比 / 补边 / 拉伸三种模式 | ✅ | ✅ | — |
| EXIF 方向自动规整 | ✅ | ✅ | 同一份 `kamadak-exif` 解析 |
| EXIF / GPS 剥离（默认）与保留（开关） | ✅ | ✅ | 默认剥离，UI 明示「默认不保留元数据」 |
| 透明 → JPEG 的背景填充策略 | ✅ | ✅ | 纯色/白/黑三选一，默认白；不做「自动取边色」（不可预测） |
| 格式转换（7 种互转） | ✅（AVIF 目标除外） | ✅ 全格式 | 转换＝解码+重编码，参数与压缩共用 |
| 批量图片 | ⚠️ Worker 池 1–2，一次 ≤50 张 | ✅ rayon + 队列可配 | 池大小取 `min(2, hardwareConcurrency-1)` |
| 大图（>20 MP） | ❌ 开始前中止 | ✅ | `DIMENSION_LIMIT` + 桌面版引导；wasm 32 位地址空间 + 峰值内存模型（20 MP ≈ 320 MB） |

## 2. 视频

| 功能 | Web（在线版） | 桌面版 | Web 侧的原因 / 限制原文 |
|---|---|---|---|
| 视频压缩（改 CRF/码率/分辨率/帧率） | ⚠️ WebCodecs 路线，≤200 MB 且 ≤5 min | ✅ 全格式、无上限（流式 + 子进程） | 无 COOP/COEP → 无 SharedArrayBuffer → wasm 不可能多线程；WebCodecs 是唯一现实路径 |
| 容器输出 | ⚠️ MP4（H.264/HEVC 视浏览器）、WebM | ✅ 全部（MP4/MKV/MOV/WebM/AVI…） | mux 用 mp4-muxer / webm-muxer（MIT）；不手写 muxer |
| 输入格式 | ⚠️ 取决于浏览器能解封装的容器 | ✅ 全部 | WebCodecs 不解封装，容器解析用 mp4box.js；MKV/MOV 等容器能力取决于浏览器 |
| 编码器可选 | ⚠️ 浏览器提供的（通常 H.264/VP8/VP9/AV1，含硬件加速） | ✅ 硬件（VideoToolbox/NVENC/QSV/AMF/VAAPI）+ 软件 | 编码器由浏览器/OS 决定，我们不打包编码器 |
| 音频 | ⚠️ Chrome/Edge 可用；Safari < 26 无 AudioEncoder | ✅ | Safari 26+ 才有 AudioEncoder，之前只能处理无声视频 |
| HEVC | ⚠️ 不保证 | ✅（构建支持时） | 浏览器 HEVC 编码支持参差，UI 不承诺 |
| GIF 导出 | ⚠️ 小尺寸短时长（走 canvas 逐帧） | ✅ FFmpeg palettegen/paletteuse | Web 端不打包 ffmpeg 时用 canvas，质量与速度都有限 |
| 抽音频 | ⚠️ 仅容器内音轨直接提取（不重编码） | ✅ 任意格式/码率 | 重编码需要编码器 |
| 封面帧 | ✅ | ✅ | Web 用 WebCodecs 解一帧，桌面用 ffmpeg |
| 元数据 / 首帧预览 | ✅ 轻量（mp4box.js 解析头部） | ✅ ffprobe 全量 | Web 只解析需要的字段，不解析整棵树 |
| 批量视频 | ❌ | ✅ | 浏览器内存与时长都撑不住 |
| 可选降级：ffmpeg.wasm 单线程 | ⚠️ **用户手动点击才下载**（31 MB raw / 9.7 MB gzip） | — | 分包、GPL-2.0-or-later 声明常驻；绝不预取，否则单人吃掉月流量预算的 80% |

**视频三路线裁决结论**（详见 `docs/ARCHITECTURE.md` §6）：
- **A. WebCodecs + 宽松许可 muxer = Web 默认**。理由：包小（约 150 KB br）、无 GPL、硬件加速；代价是容器与编码器由浏览器决定。
- **B. 单线程 ffmpeg.wasm = 可选降级**，用户点击才下载。理由：格式覆盖最全，但 9.7 MB gzip 且慢 5–20 倍；GPL 义务不可回避。
- **C. Tauri FFmpeg sidecar = 桌面唯一路径**。理由：全格式、硬件编码、流式大文件，三者都要原生进程。

## 3. PDF

| 功能 | Web（在线版） | 桌面版 | Web 侧的原因 / 限制原文 |
|---|---|---|---|
| PDF → 图片（DPI、页码范围、png/jpeg/webp） | ✅ ≤100 页 | ✅ 全页数、高 DPI、并行 | pdf.js 渲染（415 KB br），按页渲染 + 虚拟化 + 缓冲池回收 |
| 长图拼接导出 | ✅ | ✅ | 受 canvas 最大尺寸限制（Chrome 约 16384 px 单边），超限自动分片 |
| 合并 / 拆分 / 旋转 / 抽页 | ✅ | ✅ | Rust `lopdf`，字节级重排，两端同一份 |
| 提取文本 | ✅ | ✅ | 内容流 + ToUnicode CMap；扫描件无文本层，UI 明示「这是图片型 PDF」 |
| 提取图片 | ✅ | ✅ | 从 XObject 取原始流 |
| 加密 PDF（有密码） | ⚠️ 支持打开并输入密码；部分加密算法不支持 | ✅ | 仅 RC4/AES-128/AES-256 常见组合；不支持时报 `DECODE_FAILED` 并说明 |
| >100 页 | ❌ 开始前中止 | ✅ | `PAGE_LIMIT` + 桌面版引导 |

## 4. 文档（Word ↔ PDF）

| 功能 | Web（在线版） | 桌面版 | 限制原文（**必须常驻显示**，不许折叠） |
|---|---|---|---|
| Word(.docx) → PDF | ⚠️ 仅结构化 | ✅ LibreOffice headless 优先，失败降级结构化 | 「浏览器内没有 LibreOffice，只能按结构化方式排版。**会丢失**：嵌入字体、分栏、浮动图形/文本框、页眉页脚、脚注、批注、修订、域、复杂表格边框、目录、公式。复杂文档请用桌面版。」 |
| PDF → Word(.docx) | ⚠️ 仅结构化 | ✅ 同上 | 「只还原文本段落与简单表格。**会丢失**：版式、图片位置、字体、表格合并单元格。扫描件需先 OCR（本项目不做 OCR）。」 |
| 中文字体 | ✅ 子集嵌入（Noto Sans SC，OFL 1.1，1.27 MB woff2） | ✅ | 子集化在构建期完成；运行期只做 glyph 映射，不加载整字体 |
| 保真度承诺 | ❌ **不承诺** | ⚠️ LibreOffice 保真度高但非无损 | UI 常驻「可能丢失排版」声明；禁止出现「无损/高保真」字样（CI 里可做文案扫描） |

## 5. 通用

| 功能 | Web（在线版） | 桌面版 | 说明 |
|---|---|---|---|
| 批量队列 | ✅（Worker 池 1–2） | ✅（rayon + 子进程池可配） | 单任务进度 + 总进度 |
| 取消 | ⚠️ 只能「终止级」取消（`worker.terminate()`） | ✅ 硬取消（信号 + 进程树 + 清理临时文件） | `capabilities().cancel.hard` 暴露差异 |
| 暂停 | ⚠️ 仅队列级（不再取新任务） | ⚠️ 同 | `running` 任务不能暂停（wasm 同步执行；FFmpeg 的 SIGSTOP 在 Windows 无对应语义），只给取消 |
| 重试 | ✅ | ✅ | 失败/取消后，`attempt ≤ 3` |
| 原图/结果对比预览 | ✅ OffscreenCanvas / ImageBitmap | ✅ 同一组件 | 桌面端也用 WebView 画预览，不用原生窗口 |
| 输出命名规则 | ✅（模板 + 冲突自动加序号） | ✅（同 + 目录） | 默认 `{原名}-{参数摘要}.{ext}` |
| 覆盖确认 | ✅ | ✅ | 桌面端额外校验目标路径存在 |
| 体积节省统计 | ✅ | ✅ | `(in-out)/in`，无损优化时显示「-0%」而不是隐藏 |
| 最近任务 | ✅ IndexedDB（≤100 条 / ≤512 KB） | ✅ 本地配置文件 | **只存文件名与参数**，不存文件内容、不存路径（桌面端存路径也只在用户开启「记住最近目录」时） |
| 离线 | ⚠️ 首次在线加载后由 SW 缓存 | ✅ 完全离线 | Web 首次必须联网；之后外壳 + 已用分包可离线 |
| 本地日志 | ✅ 内存环形缓冲（≤200 条） | ✅ 落盘 `app_logs/`，可开关 | 不记录文件内容；路径打码为文件名 |
| 硬件编码探测 | — | ✅ | 桌面设置页显示可用编码器列表 |
| 三平台 | 任意现代浏览器 | macOS(已验证) / Windows / Linux（CI 出包，标注未验证） | 见 `docs/COMPATIBILITY.md` |

## 6. 阈值（唯一来源 `crates/core/src/common/limits.rs`）

| 项 | Web | 桌面 | 依据 |
|---|---|---|---|
| 图片像素数 | 20 MP | 无（仅受磁盘/内存） | `docs/CONTRACTS.md` §7 的内存峰值模型：20 MP ≈ 320 MB 峰值 |
| 图片文件大小 | 20 MB | 无 | 与像素数互为兜底（20 MB 的 PNG 可能只有 2 MP） |
| 单次批量图片数 | 50 | 无 | Worker 池 1–2，队列过长只会让用户等更久 |
| 视频文件大小 | 200 MB | 无 | 浏览器 `File` 与 wasm 线性内存的现实边界 |
| 视频时长 | 5 min | 无 | WebCodecs 逐帧处理，时长直接等于内存与时间 |
| PDF 页数 | 100 | 无 | pdf.js 每页 canvas 的内存，配合虚拟化 |
| 预估峰值内存 | 512 MB | — | wasm 32 位地址空间的保守值（理论上限 4 GB，但不该逼近） |
| 同时运行的视频任务 | 1 | 可配（默认 2） | 浏览器解码器实例有限；桌面可多开进程 |

**超限的统一行为**：**开始前**中止（`probe_*` 阶段就能算出），返回带 `desktopHint: true` 的错误，弹窗给 `https://github.com/lucky845/media-toolbox/releases/latest` 链接。绝不允许「跑到一半失败」或「假装能处理」。

## 7. 这张表怎么用（工程约束）

1. **UI 不硬编码**：`CapabilityBadge` 读 `capabilities()`；表里的 ⚠️/❌ 是文档与文案来源，不是 `if` 分支来源。
2. **测试断言这张表**：`tests/limits.test.ts` 对每个 ⚠️ 项断言「UI 上一定有提示元素」，防止新增功能时忘记挂提示。
3. **README 与站内页从这张表派生**：两边措辞可以不同（README 更工程化，站内页更面向用户），但「✅/⚠️/❌」的判断必须一致；CI 里 `scripts/check-capability-docs.mjs`（Phase 4 落地）比对两份表格的功能名集合。
4. **改动流程**：加功能 → 先改这张表 → 再改代码 → 再改站内文案。顺序不能反，否则文案会落后于实现。
